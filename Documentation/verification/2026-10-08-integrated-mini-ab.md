# 統合ブランチの Mac mini 交互比較（2026-10-08）

`speed/integrate` b93420f（LZMA / PPMd / zstd encoder 高速化、debug 試験短縮、writer の複数 core 化）を
base f273d34 と比べた。Mac mini M4（10 core、16 GB）、macOS 27.2、Xcode 27.0、他の作業なし。

## 方法

- harness は b93420f の `Benchmarks/Sources/GyoshukuMulticore` と `Benchmarks/Package.swift`。base は `git archive f273d34` に同じ
  harness を置いた。両版とも `swift build -c release --disable-sandbox -debug-info-format none`、`-enable-testing` なし。
- 三本を交互に best-of-5 で計測した。base、base の executable の複製（表の base2。測定の揺れの床）、新版。順序は
  `multicore.py measure --profile round3` と同じく回転・反転する。
- zstd encoder の変更で ZIP Zstd の出力 byte は base と変わる。このため `multicore.py` の同一性検査を作業用の複製だけで
  「base と base2 が一致」「新版が thread 数によらず一致」の二群に分け、出力サイズ比を記録した（repository の script は変更しない）。
  ZIP Zstd 以外は全条件で base と新版の SHA-256 も一致した。
- run1 は round3 profile の既定（tree / single / single16r / small / lha-mixed を t=1・12、corpus 4 方式を t=12）。
  run2 は 256 MiB corpus の他の方式を t=12。LHA の小入力は t=12 と t=10 で各 10 回を追加した。
- raw は `2026-10-08-integrated-mini-ab.{run1,run2,lha-t12,lha-t10}.jsonl`。load は各最短 sample の 1 分値。

## 判断

- 256 MiB corpus は t=12 で ZIP Zstd 11.2 倍、ZIP PPMd 4.8 倍、ZIP XZ 3.9 倍、7z PPMd solid 4.0 倍、LHA LH7 3.7 倍、
  ZIP LZMA 3.5 倍、7z LZMA solid 3.0 倍、7z LZMA2 solid・ZIP BZip2 2.5 倍、7z BZip2 solid 2.4 倍。
- 1 thread の codec 改善は ZIP Zstd 1.3〜6.8 倍（small 1.3、tree 1.8、10 MiB 4.5、16 MiB 乱数 6.8。出力 +0.12% 以内）、7z LZMA（LZMA1）1.36 倍。既定 level の LZMA2 / XZ は
  base と同等（自前 LZMA の既定 level は以前から xz と同程度で、改善は level 1 / 3 が中心）。
- 既に並列だった経路（ZIP Deflate、tree / small の 7z LZMA2、単一入力の LZMA2 / XZ）と逐次の BZip2 単一入力は変わらない。
- 残る退行は LHA の 10 MiB + 小 file 混在の t ≥ 10 で 3〜5%（約 1.5 ms）。揺れの床（±2%）を超えるが、base2 を含む
  中央値でも 1.06 以下、単一の 10 MiB は 1〜3%。小 member の項目窓の管理費とみられ、今回の範囲では受け入れる。
