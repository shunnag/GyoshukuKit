## Implementation and release-note text

Added `ArchiveAddition`, `ArchiveAdditionEvent`, `ArchiveAdditionError`, the protocol/default batch
method and writer/editor implementations. Callbacks run synchronously on the caller thread;
progress sessions and completion events stay in index order. Source failures carry the smallest
failed index, the original archive path, and the source URL (including recursive descendants).
Cancellation and callback errors retain their original types. A closed additions interface still
rejects additions without poisoning the instance.

Small regular files use a window of at most `resolvedCompressionThreads` jobs, with at most four
source descriptors open. Each worker checks O_NOFOLLOW open, identity/mode/size/mtime, exact length,
EOF and a final fstat before returning bytes. Hooks are captured on the caller, not looked up in GCD.
Failure cancels the limiter, abandons queued work and joins workers before returning. Per-item
caller autorelease pools and worker autorelease pools keep transient allocations bounded. Large-file and recursive fallbacks retain
that item's first lstat signature while draining earlier jobs, so an earlier didFinish callback cannot
replace a later fallback source unnoticed.
ZIP shares its existing ordered pipeline between file jobs and deflate blocks. Complete single-block
entries use one combined local-header/payload write; AES salt/encryption remains ordered on the caller.
Deflate streams are reset per pthread and released by the pthread-key destructor.

Name checks remain solely in `reserveEntryName`. Batch reserves before open, so a name error may
precede a read error on the same item. On ZIP's live-name budget transition, the rebuilt table includes
queued reservations. The original function body and scan-budget semantics are unchanged.
The existing tar/7z/LHA serializers already accept read closures and need no changes. Prefetch draining
does not flush tar compressor buffers. Rewriter `.end` records additions and uses an internal batch
with expected signatures and the P6 meter at commit; its commit errors remain unwrapped.

The benchmark accepts `--mode batch`, using the same timed sorted preorder as items.
`Documentation/design.md`, benchmark README and CHANGELOG Unreleased describe these changes.
These paragraphs are the release-note text for the orchestrator; Documentation/releases was not edited.

One validation repair outside the main prefetch files: the existing test-only
`CompressedTarSpliceWriter.injectFault` midpoint bit flip could change an unused deflate code or padding
without changing decoded bytes. `CompressedTarLifecycleTests.testHostVolume` failed identically on
untouched S38 (two assertions). For encoded gzip only, the injection now sets the first block's BTYPE
to the reserved value 3. The existing assertions were not changed, and the S38 reproduction passes
