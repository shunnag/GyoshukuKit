## 実装

`TarChunkLimits` は `1 <= packing <= piece`。gzip / bzip2 の `init(limit:)` は uniform のまま。
小さな member（header 群 + 本文 + padding）を packing まで詰め、大きな member は header 群と本文を
分けて piece ごとに切る。最後の piece は padding を含み、tar 終端は独立する。
大きな member の最後の境界に届いた判定には、境界へ届く前の上限を使う。

| 用途 | tar.xz の値 |
|---|---|
| hint あり writer と updater の橋 | packing 4 MiB / piece 16 MiB |
| hint なし入力 / 組立の予約 | piece 16 MiB の固定幅 |
| 隣の小さな chunk の吸収 | packing / 16 = 256 KiB |
| encode cache | threads × piece × 2（8 threads で256 MiB） |
| `nextEditReencodesEverything` | piece 16 MiB |
| 7z の片 | 16 MiB（変更なし） |

`OrderedChunkPipeline` の重みは入力 byte。limit > 0 かつ 0 < weight <= limit だけが軽い。
重い未出力 item が threads 以上、または全 item が `2 × threads + 1` 以上の間は先頭を出力する。
次に入れる item の重みは見ない。既定 limit/weight は0で、従来どおり全 item を数える。
tar.xz の threads > 1 だけ64 KiBを設定し、writer・updater preflight・updater 書出しに適用する。
運ぶ item / cache 済み item は weight 0。取消し・失敗・順序・自己照合は既存の経路を保つ。
入力の上界は `(threads + 1) × (piece + 64 KiB)`。P6-G の後続作業でこの式と既存の `weight:` を使う。
