## Changes and test coverage

`TarWriter` now supplies member header/body lengths and a separate end-of-archive hint. The shared `TarChunkLayout` keeps at most two pending region ends, calculating fixed-size subdivisions while receiving input. Ordinary members stay together; large header groups and bodies each begin and end at chunk boundaries. The EOF marker and record fill form one final chunk, including with reduced test limits.

Gzip keeps the trailing 32 KiB across short chunks in hint mode. Unhinted compressors retain their original framing and dictionary behavior. `XZFraming` contains the existing stream/block/Index/footer serialization; tar.xz's 16 MiB default is separately named `ParallelXZCompressor.defaultBlockSize`. Optional `TarWriter.memberLayouts` records header-group start, data start, and padded end.

Seven new `TarChunkLayoutTests` cover:

- Actual gzip `Z_BLOCK` synchronization points, bzip2 streams, and XZ Index lengths versus an independent Swift reference rule.
- Small, exact-limit, over-limit, multi-chunk, empty, directory, symlink, pax, and oversized-pax cases.
- Dedicated zero-only EOF chunk, including a 10,240-byte EOF with an 8 KiB test limit.
- Byte identity at 1/4/8 threads and with 997-byte reads.
- Gzip dictionaries spanning short chunks, compared with serial framing using the preceding full 32 KiB.
- Original unhinted fixed-width framing, computed with the real encoders rather than an OS-dependent XZ hash.
- `ArchiveRewriter` output and opt-in member-layout recording.

The public writer's existing 65,535-byte name limit remains in place. The oversized bzip2 pax fixture uses internal `TarWriter` to exercise a header group larger than 500,000 bytes. Only the two existing assertions permitted by G1 were changed; external compatibility tests were retained.
